## 📊 Ключові висновки EDA-аналізу

### 1. Дисбаланс класів (`01_class_imbalance.png`)
* **Відмова (Клас 0):** 39 922 клієнти (**88.3%**).
* **Згода (Клас 1):** 5 289 клієнтів (**11.7%**).
* **Висновок:** Сильний дисбаланс класів вимагає обов'язкової **стратифікації** при розбитті на Train/Test та використання метрик **PR-AUC, ROC-AUC, F1-score**, оскільки стандартна точність (Accuracy) буде оманливо завищеною.

### 2. Розподіли ознак: Медіана vs Середнє (`02_numerical_distributions.png`)
* **Вік (Age):** Розподіл симетричний, близький до нормального (медіана 39 р., середнє 40.9 р.).
* **Баланс (Balance):** Сильний правий скіл — медіана **448 €**, але заможні клієнти (до 102 127 €) зсувають середнє до **1 362 €** (трикратний розрив!).
* **Тривалість (Duration):** Медіана 180 с (3 хв), середнє 258 с (хвіст до 4 918 с).
* **Кількість контактів (Campaign):** Медіана 2 дзвінки (97.4% клієнтів мають $\le 10$ дзвінків).

### 3. Аналіз аномалій за правилом 1.5 IQR (`03_outliers_iqr_boxplots.png`)
* Верхня межа 1.5 IQR для балансу — **3 462 €** (10.5% клієнтів формально вважаються «викидами»).
* Верхня межа для тривалості — **643 с** (7.2% клієнтів).
* **Обґрунтування:** Ці значення не є помилками збору даних, а відображають реальних заможних клієнтів та тривалі результативні консультації. Їх видалення призвело б до втрати ключових цільових клієнтів. Тому для масштабування обрано **`RobustScaler`**, який використовує медіану та інтерквартильний розмах (IQR), залишаючись нечутливим до екстремальних значень.

## ⚙️ Логіка конвеєра обробки даних (`data_preprocessing.py`)

1. **Запобігання Data Leakage:**  
   Поділ вибірки `train_test_split(..., test_size=0.2, stratify=y, random_state=42)` здійснюється **до** будь-якого масштабування чи заповнення пропусків. Усі параметри обчислюються суворо на навчальній вибірці (`.fit(X_train)`).
2. **Feature Engineering:**  
   Додано бінарний індикатор `Previously_Contacted = (Pdays != -1).astype(int)` для збереження семантики первинних звернень (81.7% клієнтів не контактували в попередніх кампаніях).
3. **Архітектура `ColumnTransformer`:**
   * **Числові ознаки (8):** `SimpleImputer(strategy='median')` $\to$ `RobustScaler()`.
   * **Порядкова ознака (`Education`):** `OrdinalEncoder` з явним збереженням ієрархії: `unknown` (-1) $\to$ `primary` (0) $\to$ `secondary` (1) $\to$ `tertiary` (2).
   * **Номінальні ознаки (8):** `SimpleImputer(strategy='most_frequent')` $\to$ `OneHotEncoder(drop='first', sparse_output=False)` для запобігання пастці фіктивних змінних (dummy variable trap).
4. **Результат:** 41 фінальна ознака для кожного спостереження без втрати жодного рядка.
